2. Uploaden naar GitHub

  1. Open de repository op github.com.
  2. Klik op Add file, dan Upload files.
  3. Sleep alle gewijzigde bestanden er in een keer in.
  4. Onderaan op de groene Commit changes klikken.

Upload altijd alles in een keer. Bij meerdere uploads kort na elkaar start GitHub meerdere publicaties tegelijk en krijg je de foutmelding dat er al een deployment bezig is. Een commit is een publicatie.

Na de commit publiceert GitHub automatisch. Onder het tabblad Actions zie je de voortgang. Groen vinkje betekent live. Zie je in de browser nog de oude versie, ververs dan met Ctrl+F5.

Iets kleins aanpassen

Downloaden en opnieuw uploaden hoeft niet. Klik in de repo op het bestand, dan op het potloodje rechtsboven. Je bewerkt direct in de browser en klikt onderaan op Commit changes.

3. Het formulier werkend maken

Het kennismakingsformulier staat op de site maar verstuurt nog niets. Losse HTML kan geen mail versturen, daar is een tussendienst voor nodig. Formspree is gratis tot 50 aanvragen per maand.

  1. Ga naar formspree.io en maak een account aan met ylboost@outlook.com.
  2. Maak een nieuw formulier. Je krijgt een adres als https://formspree.io/f/xayzbwqd.
  3. Open index.html, zoek op JOUW_FORMSPREE_ID en vervang dat door het laatste stukje, in dit voorbeeld xayzbwqd.
  4. Opslaan en uploaden. De eerste aanvraag moet je in je mailbox eenmalig bevestigen.

Test hem daarna zelf een keer, dat is de enige manier om zeker te weten dat het werkt.

6. Checklist voor livegang

  1. Formulier gekoppeld en zelf getest.
  2. KvK-nummer en btw-id ingevuld op alle drie de pagina's.
  3. Echte reviews geplaatst, of de hele sectie Ervaringen verwijderd. Nepreviews zijn erger dan geen reviews.
  4. Blogsectie gevuld of verborgen. Placeholderteksten horen niet op een live site.
  5. Portretfoto geplaatst.
  6. Opleidingsstatus gecontroleerd. Ik heb "in opleiding" bij NHA weggehaald, controleer of dat klopt.
  7. Tekst over vergoeding gecontroleerd tegen de werkelijke BGN-status. Er staat nu geen garantie meer in.
  8. Registratielogo's alleen tonen als de registratie echt rond is, en volgens hun gebruiksvoorwaarden.
  9. Alles op een telefoon doorlopen: menu, knoppen, formulier, uitklappers, footer.
  10. Domein gekoppeld en HTTPS aangezet.

7. Eigen domein koppelen

  1. Koop het domein, bijvoorbeeld bij TransIP. Let op het verlengtarief.
  2. In GitHub naar Settings, dan Pages. Vul bij Custom domain het domein in en klik Save.
  3. Bij de registrar, in het DNS-scherm, vier A-records op @ zetten: 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153.
  4. Plus een CNAME op www naar gebruikersnaam.github.io.
  5. Wacht tot de DNS is doorgekomen, meestal binnen een uur. Zet dan in GitHub Enforce HTTPS aan.

Zet bij de registrar ook de whois-afscherming aan, anders staat het woonadres publiek zichtbaar.

8. Waar je op moet letten

Aanpassen betekent in de code werken. Er zit geen beheeromgeving achter. Teksten en prijzen wijzigen gaat via het bestand. Voor een paar wijzigingen per jaar is dat prima. Wil je wekelijks bloggen, dan loop je hier op termijn tegenaan en is WordPress of Squarespace een betere keuze.

Werk niet met zijn tweeen tegelijk in hetzelfde bestand. Wie het laatst commit, overschrijft de ander zonder waarschuwing. Even afstemmen wie er aan zit.

Het e-mailadres. Op de site staat nu ylboost@outlook.com, zoals in het ondernemingsplan. Zodra het domein er is, is info@yulehealthboost.nl een stuk professioneler. Dat kan met een simpele doorstuur-alias bij de registrar, gratis.

Het logo heeft geen transparante achtergrond. Op de site geen probleem, want daar staat het overal op zwart. Voor drukwerk, visitekaartjes of Instagram heb je een versie met transparante achtergrond nodig, liefst als SVG of PDF. Vraag die op bij wie het logo gemaakt heeft.
